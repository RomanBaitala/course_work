# Технічні вимоги та аналіз предметної області (Варіант 3)

## 1. Загальна інформація
- **Тема проєкту:** Система управління готелем (Hotel Management System)
- **Дисципліна:** Документування програмного забезпечення та шаблони проектування
- **Університет:** Національний університет «Львівська політехніка»

---

## 2. Функціональні вимоги до системи

### 2.1. Каталог номерів
- Відображення переліку номерів з розподілом за категоріями:
  - Економ (Economy)
  - Стандарт (Standard)
  - Люкс (Deluxe / Suite)
- Фільтрація та пошук номерів:
  - Діапазон цін (від / до)
  - Кількість спальних місць
  - Зручності (кондиціонер, Wi-Fi, балкон, міні-бар тощо)
- Картка номера: фотогалерея, детальний опис, місткість, базова ціна за добу.

### 2.2. Бронювання та розрахунок вартості
- Вибір дати заїзду (check-in) та виїзду (check-out).
- Перевірка доступності вибраного номера на вказаний період.
- Вибір додаткових послуг:
  - Харчування (сніданок, напівпансіон, all inclusive)
  - Трансфер (аеропорт / вокзал)
  - SPA-комплекс
  - Додаткове спальне місце
- Автоматичний розрахунок підсумкової вартості залежно від терміну перебування, тарифного плану та обраних послуг.

### 2.3. Персональний кабінет клієнта
- Авторизація та реєстрація клієнтів.
- Перегляд історії власних бронювань (активні, завершені, скасовані).
- Можливість скасування або продовження бронювання.
- Програма лояльності:
  - Накопичення бонусних балів за кожну добу проживання.
  - Використання бонусів для оплати наступних бронювань.

### 2.4. Адміністративна панель та звіти
- Додавання, редагування та видалення номерів і послуг.
- Перегляд списку всіх бронювань та зміна їхніх статусів.
- Звіти для керівництва готелю:
  1. **Завантаженість номерів** (відсоток зайнятих номерів, календар зайнятості).
  2. **Фінансові показники** (дохід по місяцях, виручка за категоріями номерів).
  3. **Аналітика клієнтів** (список постійних клієнтів, сума витрат, частота відвідувань).

---

## 3. Нефункціональні вимоги та архітектура
- **RESTful API:** Всі клієнтські запити обслуговуються через стандартизовані REST ендпоінти із відповідними HTTP методами (GET, POST, PUT, DELETE).
- **База даних:** Збереження сутностей номерів, бронювань, користувачів, послуг, платежів та транзакцій бонусів.
- **GoF-патерни:** Обов'язкова інтеграція породжувальних, структурних і поведінкових шаблонів відповідно до методичних вказівок.
- **Принципи проектування:** Дотримання SOLID, GRASP та Clean Architecture.
